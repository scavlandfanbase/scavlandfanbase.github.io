Status: isolated preparation. No live route, database migration, deployment or Hub enablement. VS owns its local editor branch; this checkpoint does not modify those files.

## Verified repository boundary

The existing r1-private-drafts proposal maps domain pages to content_edit. Admin Hub maps content_edit to Public Content. Neither is a complete Page Builder integration: production.mjs currently routes shared-item, shared-attachment, evidence-review and the legacy Items/Vendors catalogue workflow only. The existing page draft RPC provides load/save revisions, but not page allocation, listing, archive, preview approval or publication. Do not expose it as a complete builder service.

## Implemented and tested

page-request.mjs defines a pure, unused request envelope for domain page-builder: list, load, create, save and archive. Mutations carry UUID request IDs. Saves/archives require positive safe integer expected versions; create has no client-assigned permanent ID. Saving requires payload identity to match pageId. Extra envelope keys, including forged actor/time/permissions/approval/public base, are refused. Results are cloned so the caller's editor buffer remains unchanged, including literal Unknown values.

This boundary does not authenticate callers, authorize access, validate page content, generate IDs, store data, deduplicate retries or publish anything. Those guarantees must be implemented and tested in the following checkpoints. Structured page validation remains the reviewed VS model's responsibility, with server-owned image/address context; an object passing this envelope is not a valid page by itself. Publish/approve/preview are deliberately not defined yet.

Independent verification: node scripts/test-page-request.cjs passes valid commands, every missing required field, protected/unknown envelope fields, unsupported actions, invalid IDs/versions, identity substitution and deep-copy preservation. git diff --check passes. No SQL or browser changes were made, so this checkpoint does not claim production or UI acceptance.

## Private storage preparation completed

Added unapplied supabase/proposals/page-builder-storage.sql with three private RLS-enabled tables: request allocations/preparations, immutable saved versions and retained address reservations. Direct SELECT/INSERT/UPDATE/DELETE grants are revoked for anon, authenticated and service_role. Empty-search-path private definer functions perform narrow operations through invoker wrappers; anon cannot call either wrapper. Service-only preparation relies on the eventual transport checking real caller Auth/content_edit and the trusted model before supplying content. Caller commit/load/list independently check current DB content_edit permission; revocation also blocks old receipt replays.

Create allocation assigns a database UUID and binds actor/request/action/exact command. A null preparation supports allocation recovery; unprepared content cannot be committed. Prepared content cannot change. Commit accepts only a matching prepared receipt, writes server actor/time, and returns the original version on exact retry even after later changes. Archive saves a new version containing unchanged saved content and keeps prior versions. New saves after archive are refused; restore/history UI is not implemented. Address reservations persist through rename/archive. Trusted public-route/reserved-address checks are still required before output; this table alone does not authorize a public address.

Concurrency deliberately serializes page catalogue mutations after request locking. This simple global write lock coordinates identity/version/address checks for the initial small Admin workload; no DB lock crosses a network request. Separate prepare/commit intervals recheck the head during commit. List is a bounded 100-summary UUID-keyset query with p_after; transport request pagination still needs wiring. Full draft bodies are returned only by load, not list. Maximum expected version now leaves room for the next PostgreSQL integer revision.

Verification: local PGlite storage suite passes allocation recovery, changed actor/command/payload refusal, missing preparation, server actor/time, exact/old receipt replay, stale saves, archive preservation, archived refusal, address collision after rename/archive, bounded-list shape, permissions/revocation, direct grants, RLS, empty search paths and retained counts. Six independent PostgreSQL 17.11 READ COMMITTED scenarios passed with observed advisory-lock waits: allocation retry, changed allocation, competing saves, exact commit retry, archive versus save and rollback recovery. Fixture DBs were dropped and the portable server stopped. Request boundary and existing release-gate suites pass. No production SQL, secrets, migration history or live route changed.

Reviewed current Supabase changelog and Database Functions documentation plus the Postgres skill's lock-order and RLS guidance. New work uses ordinary PostgreSQL locks/UUID/JSON rather than the newly changed extensions. Sources: https://supabase.com/changelog and https://supabase.com/docs/guides/database/functions . No live advisor run is claimed for this unapplied proposal; production advisor/readiness review belongs to its later coordinated rollout.

Next: trusted model/context integration and authenticated transport, including strict paginated list envelopes and lost-response recovery across allocation, preparation and commit. Keep Page Builder release controls off until combined acceptance and publication recovery are complete.

## Authenticated adapter and trusted model/source prepared

Added page-api.mjs, still unused by production.mjs. PAGE_BUILDER_ENABLED must explicitly be true in its test/integration environment; disabled adapter returns 503 with no network calls. Caller-JWT list/load preflight checks current content_edit before trusted preparation. Mutations resolve the actor through Auth /user; service credentials are used only for preparation, with commit performed using the real caller JWT. Strict envelope/body limits, 15-second network bounds, generic errors, no-store responses and existing-site CORS are included. The paginated list envelope accepts a UUID after cursor and returns bounded summaries/nextCursor. Load leaves historical invalid content openable for repair.

Creation obtains its durable allocation, injects the permanent UUID, then validates through the reviewed VS model. page-model.mjs adapts only the UMD wrapper from e8ad5a6 into an ESM module; a SHA-256 reconstruction test confirms the original model body is unchanged. Raw browser asset/address inventories are never accepted. Already-prepared exact retries reuse their original content/receipt rather than replacing it with newly generated identity or content; commit still checks current permission and revision.

Default page-source.mjs reads main once, then reads the complete tree and approved image inventory at that commit. Only inventory paths that pass the model's safe images rule and exist as regular Git blobs are approved; missing paths, symlinks, traversal and external images are excluded. Truncated trees, missing inventory/configuration and nonadvancing private-page pagination are refused. Private current identities are gathered through caller-authorized keyset list RPCs. Existing pages/*.html currently causes refusal: the publisher must first define and validate a public identity manifest rather than infer page ownership from a matching address. Retained private address reservations remain enforced at commit. Context snapshot changes across network calls remain subject to commit checks and later output revalidation; this is not an atomic Git/database transaction.

Verification: new local SQL/API suite passes caller authorization, protected-envelope/content refusal, body size limit, model validation, server allocation, response-loss-after-commit retry without a duplicate revision, changed-request/stale refusal, archive, missing context/configuration, permission revocation and model fingerprint parity. Trusted-source fixture suite passes commit pinning, actual approved image membership, pagination, missing/truncated sources, symlink/traversal refusal and unknown public-page refusal. Existing request/storage and release-gate suites, syntax and whitespace checks pass. Auth and Git are fixture transports; no genuine live authentication/production reads or writes are claimed by these tests.
